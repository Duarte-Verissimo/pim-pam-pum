Resumo da aplicação

Esta aplicação foi desenvolvida para a disciplina de Programação Web. O objetivo foi criar um portefólio em Django onde consigo apresentar o meu percurso académico, projetos, tecnologias, competências, formações, experiências profissionais e artigos.

Para além das páginas de consulta, a aplicação tem autenticação, permissões para gerir conteúdos, artigos com comentários, likes e avaliação por visitantes. A ideia foi construir uma base funcional, mas também simples de perceber e continuar a melhorar.

Modelação de dados

A modelação foi feita com models do Django. Cada model representa uma tabela da base de dados e define os campos e relações que a aplicação usa. Isto ajuda a manter os dados organizados em vez de guardar tudo como texto solto.

Entidades principais

O portefólio inclui entidades como licenciaturas, docentes, unidades curriculares, projetos, TFCs, tecnologias, competências, formações, experiências profissionais e registos de making of.

A área de artigos tem uma modelação própria: cada artigo tem um autor e pode receber comentários, likes e ratings. Os comentários e ratings também podem ser feitos por visitantes não autenticados.

Aplicação Django

O projeto segue a arquitetura MVT do Django. Na prática, os models representam os dados, as views tratam da lógica dos pedidos e os templates constroem o HTML mostrado ao utilizador.

Arquitetura em produção

Em produção, a aplicação corre dentro de um container Docker. O container usa Gunicorn para servir o projeto Django na porta 3000. A base de dados fica fora do container, no Neon, e é acedida através da variável DATABASE_URL.

Utilizador Servidor / VM Container Docker Django + Gunicorn Neon PostgreSQL Cloudinary

Serviços externos

  • Neon: guarda os dados da aplicação em PostgreSQL.
  • Cloudinary: guarda ficheiros multimédia, como imagens enviadas.
  • WhiteNoise: serve os ficheiros estáticos recolhidos pelo collectstatic.

Pipeline de CI/CD

O projeto tem um workflow de GitHub Actions que automatiza o build e o deploy. O pipeline corre quando há push para a branch main ou quando é iniciado manualmente.

Passos do pipeline

  1. Faz checkout do código.
  2. Entra no GitHub Container Registry.
  3. Constrói a imagem Docker do projeto.
  4. Publica a imagem em ghcr.io.
  5. Entra no servidor por SSH.
  6. Faz pull da imagem mais recente.
  7. Para e remove o container antigo.
  8. Cria um ficheiro temporário com os secrets de produção.
  9. Arranca um novo container com a imagem atualizada.

Este processo reduz trabalho manual e torna o deploy mais repetível. Os dados sensíveis, como credenciais do Neon e Cloudinary, ficam guardados nos secrets do GitHub Actions.

Making of

Durante o desenvolvimento fui melhorando a aplicação por etapas. Primeiro ficaram as páginas principais e a modelação; depois vieram áreas como autenticação, permissões, artigos, comentários, ratings, deploy e organização da página Sobre.

O resultado é uma aplicação funcional que junta a parte técnica da disciplina com uma apresentação do meu percurso. Ainda pode ser melhorada, mas já tem uma estrutura pronta para continuar a crescer.
